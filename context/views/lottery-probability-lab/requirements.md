# 双色球概率实验室 - 需求文档

## 功能列表

### 本地开奖数据

1. **CSV 兜底导入** - 用户可在官方同步不可用时粘贴符合约定列结构的 CSV 内容批量导入；页面不再提供逐期手动新增开奖入口。
2. **数据校验与本地保存** - 页面校验期号、日期、红球、蓝球与重复期号；只保存完整、合法且未重复的开奖记录到当前浏览器。
3. **自动官方同步** - 页面首次无历史数据时自动全量同步官方往期；页面开启期间按北京时间每周二、四、日 21:30 自动拉取最新官方开奖并写入 IndexedDB。
4. **历史数据概览** - 页面显示已录入期数、最新期号、最近一期结果、红蓝球频率和数据来源提示。
5. **浏览器长期数据与迁移** - 页面把开奖记录、预测快照和复盘记录保存到 IndexedDB，并在首次升级时迁移旧版 localStorage 数据。
6. **备份与恢复** - 用户可导出完整 JSON 备份，也可选择合法备份文件恢复全部本地历史数据。

### 概率审计与候选计算

1. **右侧算法导航** - 右侧固定菜单以算法名称切换当前工作区：均匀组合基准、随机性审计、贝叶斯静态偏差、时间衰减偏差、组合依赖、滚动评分集成和三注覆盖优化。
2. **随机性审计** - 对历史红蓝球频率、号码对共同出现情况、近期窗口与全量窗口差异作描述性审计，明确其只能提供异常证据而不能证明未来可预测。
3. **五大组奖级覆盖候选** - 每个预测型算法都必须基于当前已保存数据实际计算 5 个奖级覆盖大组；每个大组包含一等奖锚点票、同 6 红不同蓝球的二等奖蓝球覆盖票、保留 5 红与主蓝且替换 1 红的三等奖红球覆盖票，共 15 注互不重复的合法组合。
4. **算法证明过程** - 每个大组展示算法输入窗口、锚点组合分或均匀抽样说明、备用蓝球的权重与排名、红球替换的移除 / 候补理由、回测身份和对应回测指标；证明过程解释确定性计算，不承诺未来中奖。
5. **按算法恢复候选** - 用户切换右侧算法后，工作区自动显示该算法最近一次已保存的预测快照；刷新页面、恢复备份后也从历史快照中恢复每种算法的最新候选，不能因为最后生成了其他算法而丢失当前算法显示。
6. **滚动历史回测中心** - 页面使用冻结窗口和时间顺序滚动方式，对均匀基准、贝叶斯静态偏差、时间衰减、组合依赖、评分集成和覆盖优化分别回测，展示红球平均命中、蓝球命中率、复合命中分、相对均匀基准差异、置信下界和逐期胜率。
7. **候选与证据边界** - 没有达到验证门槛的算法仍可输出“研究候选”，但必须明确其没有可验证的预测优势；只有滚动回测达到冻结门槛的算法才标为“回测通过”，但该标记也不得表述为未来中奖保证。

### 预测快照与开奖复盘

1. **不可变五组预测快照** - 每次生成候选时，保存算法、参数版本、数据截止期、生成时间、5 个大组、15 注覆盖票、每组证明过程和随机种子；历史快照不可被后续重新计算覆盖。
2. **自动开奖对照与奖级标注** - 保存新一期开奖数据后，系统将符合条件的早期预测快照与其后的首期开奖记录对照，计算命中红球数、是否命中蓝球、`6+1 / 6+0 / 5+1` 结构和一等奖 / 二等奖 / 三等奖标注。
3. **回测说明** - 页面同时展示单注理论概率、三注理论概率、红球命中超几何基线和已保存预测的经验结果；经验结果不得被表述为未来中奖概率。

## 业务规则

- **双色球号码范围**：每条开奖或候选组合必须恰好包含 6 个两位显示的红球，红球是 1–33 内互不重复的整数；必须包含 1 个 1–16 内的蓝球。红球以升序保存和展示。
- **开奖数据完整性**：期号和日期不能为空；同一期号只能保存一次。导入中每一条非法或重复记录必须被拒绝并显示原因，不能部分改写已有记录。
- **CSV 约定**：首行字段为 `issue,date,red1,red2,red3,red4,red5,red6,blue`；日期为 `YYYY-MM-DD`；导入以逗号分隔，忽略空行。
- **自动官方同步**：首次打开且没有开奖记录时，页面自动通过 [GET 开奖查询接口](api.md#get-cwl_adminfrontcwlkjsearchkjxxfinddrawnotice) 的同源代理全量同步往期；已有数据时，页面开启后会补拉官方第 1 页最新记录。页面保持开启期间，按北京时间每周二、四、日 21:30 自动同步最新开奖；若官方结果尚未发布，页面每 5 分钟重试，最长至 22:30。开发环境由 Vite 的 `/official-cwl-api` 代理转发，生产部署必须将 `VITE_CWL_API_BASE` 配置为以 `/` 开头的可用同源反向代理基址。同步中必须展示页码、收集数量和自动同步状态，且阻止并行同步。
- **官方响应规范化**：每条远程记录使用 `code` 作为期号、日期字段前 10 位作为 `YYYY-MM-DD` 日期、以英文逗号分割的 `red` 字段作为 6 个红球、`blue` 字段作为蓝球；任一字段无法满足号码范围或日期规则时跳过该条并累计提示。
- **官方同步写入边界**：首次全量同步时，所有页面均成功获取并完成本地规范化后，才将新增记录在一次 IndexedDB 写入中提交；定时或启动补拉仅请求官方第 1 页并写入其中的新增期号。已存在期号一律跳过，不能覆盖用户已经保存的记录；网络、代理、HTTP、响应结构或分页失败时，不写入本轮任何远程记录，并显示可读错误。
- **本地数据边界**：开奖记录、预测快照、开奖对照和备份恢复数据保存到当前站点的 IndexedDB；`localStorage` 只保存当前算法等轻量 UI 状态。不请求、上传或自动抓取任何第三方数据。浏览器清除站点数据、使用无痕模式或设备损坏仍可能丢失本地历史，因此用户应定期导出 JSON 备份。
- **旧数据迁移**：首次创建 IndexedDB 数据库时，页面读取旧版 localStorage 中的开奖记录、预测快照、对照记录和当前算法；仅在 IndexedDB 成功写入后标记迁移完成，且不主动删除旧数据。迁移失败时必须保留旧数据并显示可见提示。
- **备份与恢复**：导出文件必须包含备份版本、导出时间、开奖记录、不可变预测快照、开奖对照和当前算法。恢复前必须完整校验 JSON 结构、号码、期号唯一性和快照 / 对照关联；任一必需校验失败时不得改写 IndexedDB。合法恢复以完整替换当前本地数据为语义，恢复成功后重新执行待复盘快照的开奖对照。
- **审计结论边界**：频率、间隔、共现、近期变化等指标只用于审计和模型回测；页面不得使用“必中”“提高中奖概率”“必出号”等承诺性文字。
- **滚动回测窗口**：回测必须严格按时间顺序。每个预测期只能使用该期之前的数据；训练窗口固定为最近 160 期，优先评估最近 180 个可用预测期。每个预测期为每种算法以固定种子生成 3 注候选，并与实际开奖对照。
- **回测指标**：每种算法展示每注平均红球命中数、蓝球命中率、复合命中分（红球命中数加蓝球命中 0.5 分）、相对均匀基准的平均复合分差、差异的正态近似 95% 下界及单期优于均匀基准的比例。指标用于比较历史表现，不是未来概率。
- **验证门槛**：只有评估期不少于 120，且相对均匀基准的平均复合分差的 95% 下界大于 0 时，算法可以标记为“回测通过”。未通过或数据不足时仍生成自身研究候选，状态为“研究候选”；不得回退为均匀组合，也不得暗示更高中奖概率。
- **评分集成**：评分集成以最近一次滚动回测中贝叶斯静态偏差和时间衰减模型的相对表现形成非负权重；没有正向相对表现时使用等权研究组合。该过程仍不自动获得“回测通过”状态。
- **三注唯一性**：同一批次的三注候选必须各不相同；公平基线下该规则只避免重复购买，不改变任何单注的理论中奖概率。
- **预测快照不可变**：生成后的历史预测快照只可查看和参与对照；后续导入数据、切换算法或再次生成不得更改其中的号码、数据截止期和随机种子。
- **页面开启限制**：纯前端页面只有在浏览器页面保持开启时才能在 21:30 定时执行；若页面或浏览器已关闭，下一次打开页面会先补拉官方最新记录，再进行开奖对照。要在浏览器关闭时也准点同步，必须另行部署后端定时任务。
- **开奖对照规则**：对每个尚未对照的预测快照，使用数据截止期之后按日期、再按期号排序的首条开奖记录作为对照结果；每注分别计算命中红球数、命中蓝球布尔值和 `x 红 + y 蓝` 标签。
- **概率表述**：单注一等奖理论概率为 `1 / (C(33, 6) × 16)`；15 注不同组合的一等奖理论概率最多为十五倍单注概率。奖级覆盖结构只描述票面间的条件关系，不改变任何一注的理论概率。已保存预测的命中统计仅为样本结果，必须与理论概率分开展示。
- **AI 安全边界**：本轮不把任何 API Key、模型服务地址或 AI 请求放进浏览器端、IndexedDB、备份或 Git。若未来接入 AI，只能由独立后端 / 同源服务端代理持有轮换后的密钥，并且 AI 只解释已经由确定性算法生成的证明过程和回测指标，不能改写号码或声称提高中奖概率。
